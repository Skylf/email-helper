# Bug: 应用启动速度过慢，双击图标长时间无窗口反馈

**日期**: 2026-08-28
**版本**: v0.5.4
**优先级**: 高

## 现象
桌面双击 exe 图标后，需等待几十秒才出现主窗口；期间界面完全无任何反馈，
极易让用户误以为「没点到图标」或「启动失败」。

## 根因
1. **启动序列同步阻塞**：`src/main.py` 在顶层就以 `from GUI.MainGUI import MainWindow`
   同步导入整个业务树（MainEmail/NormalMode/database/activity…）及 PyQt6 全部重 DLL，
   在窗口出现之前全部堆积执行，造成超长黑屏无反馈期。
2. **打包环境冷启动慢**：Windows Defender 首次对打包 exe 及其引入的 PyQt6 DLL
   （数百 MB）做整目录实时扫描，二次启动明显变快即印证此点（环境因素）。
3. 已排除代码内重负载：`openpyxl` 均为函数内延迟加载、sqlite 连接毫秒级、
   凭据只解密 76 字符、spec 已关闭 UPX（`upx=False`）。

## 修复
`src/main.py` 重构启动流程：
1. 新增 `createSplash()`：程序化绘制启动闪屏（品牌色底 + 主标题 + 「正在加载，请稍候…」），
   无需额外图片资源即可随包分发。
2. 主窗口改为延迟加载：先创建 `QApplication` 并立即 `show()` 闪屏，
   用 `QTimer.singleShot(0, …)` 待事件循环跑起来、闪屏绘制完成后，再导入并构造主窗口，
   最后以 `splash.finish(window)` 关闭闪屏。
3. 效果：双击后即刻看到闪屏反馈，业务模块加载耗时被藏在闪屏之后，消除「没点到」的错觉。

## 验证
- 开发环境冒烟测试：闪屏位图成功绘制（460×240），主窗口正常构造显示，流程退出正常。
- 建议重新打包后真机再次验证，并引导用户将 exe 目录加入 Windows Defender 排除项
  以消除二次启动差异。
