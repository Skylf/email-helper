# Bug: 附件文件夹扫描排序错乱（数字文件 10 被排到最前）

**日期**: 2026-08-24
**版本**: v0.1C（开发中）
**优先级**: 高

## 现象
测试文件夹 `test/附件1` 下有 10 个文件：`1张伟获奖证书.pdf` … `10吴昊获奖证书.pdf`。
扫描后矩阵中第一行附件列却显示 `10吴昊获奖证书.pdf`，随后才依次是 `1、2、3…9`，
即「10」被误排到了最前面，与收件人 1~10 的对齐关系错位。

## 根因
`_scanFolderFiles` 用的是纯字符串排序（`sorted(names)`）。按字符字典序比较时，
`"10..."` 与 `"1张伟..."`：首字符都是 `1`，接着 `'0'` 与 `'张'` 比，`'0'` 的码点（0x30）
远小于中文 `'张'`，因此 `"10..."` 排在 `"1张伟..."` 之前，继而所有 `2..9` 也都排在其后。
这是把「数字作为数值」误当成「数字作为字符串」的经典问题。

## 修复
在 `src/GUI/MainGUI.py` 中：

- 新增 `AdvancedPage._naturalSortKey`：用正则 `re.split(r'(\d+)', name)` 把文件名拆成
  「数字段 / 非数字段」交替片段，数字段转成 `int`，非数字段保持字符串，作为排序键。
- 修改 `_scanFolderFiles` 的返回语句为
  `sorted(names, key=self._naturalSortKey)`，改用自然排序。

这样 `1、2、3…9、10` 会按数值升序排列，收件人 k 正确对应第 k 个文件。

## 验证
用 `test/附件1` 实测 `AdvancedPage._scanFolderFiles(...)`，输出为：

```
1张伟获奖证书.pdf
2王芳获奖证书.pdf
...
9周雪获奖证书.pdf
10吴昊获奖证书.pdf
```

数字按数值升序，修复生效。
